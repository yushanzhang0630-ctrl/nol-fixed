# onestop / runner 修改差异说明

## 比对范围与方向

本报告只依据本次上传的四个文件逐行比对，不对未上传的本地版本作推断。按代码内容，以下把 `onestop(1).py`、`runner(1).py` 作为基准版，把 `onestop(general-ver).py`、`runner(general-ver) .py` 作为修改版，列出 **基准版 → 修改版** 的差异。

| 文件 | 基准版行数 | 修改版行数 | 主要变化 |
|---|---:|---:|---|
| `onestop.py` | 1,103 | 1,350 | 座位图加载等待、选座页面识别、票档排序/座位扫描、完成选座按钮确认逻辑 |
| `runner.py` | 196 | 233 | Chrome Profile 失败时的处理策略、接手后自动切换到真正的选座标签页 |

## 一、onestop.py

### 1. `wait_and_focus_seatmap`

- **基准版：约第 86–107 行；修改版：约第 86–175 行。**
- 基准版只要发现一个 `circle.js-seat` 就返回，且每 0.5 秒轮询一次。
- 修改版增加加载观察状态：记录座位总数、可选座位数、首次出现时间和数量稳定时间；座位数变化时输出日志；对 DOM 查询异常做捕获；每 0.2 秒检查一次。
- 有可选座位时，至少观察约 0.8 秒再返回；无可选座位时，会在观察到 SeatMap 存在且数量稳定一段时间后返回，避免把 React 初始渲染的少量座位误判为完整座位图。

### 2. `choose_seat_auto`

- **基准版：约第 112–131 行；修改版：约第 180–246 行。**
- 基准版主要按当前 URL 分流：NOL 调用新版 SVG 选座，Interpark 调用旧版区域选座。
- 修改版先切回主文档，再立即检查 `circle.js-seat`；如果还没有座位图，则最多等待 30 秒，让 NOL 自动跳转或完成 SeatMap 加载。
- 等待结束后再根据 URL 判断旧版 Interpark；如果仍是 NOL 却没有找到 SeatMap，则明确返回失败并输出日志，而不是直接继续选座。

### 3. `choose_best_seat`

- **基准版：约第 598–647 行；修改版：约第 713–828 行。**
- 基准版使用 `preferred_colors()` 取得颜色顺序，再针对每种颜色分别调用 `find_selectable_seats()`；座位候选列表可能被重复扫描。
- 修改版直接解析完整票档信息 `parse_grades()`，保留 **颜色、票档名、价格**，打印从贵到便宜的排序日志。
- 修改版对整张 SVG 的可选座位只做一次主扫描，再按 `fill` 颜色分组，之后按价格从高到低依次尝试对应票档；这样减少重复查找，也能在日志里看出当前检查的票档与价格。
- 修改版对单个座位的读取/点击增加 `try/except`，并输出座位 ID、票档、价格及颜色，某个元素刚好失效时可以继续尝试后续座位。

### 4. `_click_seat_confirm`

- **基准版：约第 648–695 行；修改版：约第 829–941 行。**
- 两版都使用 Selenium `ActionChains` 对「完成選擇」执行真实鼠标点击，并检测后续状态。
- 修改版把按钮逐个检查的异常隔离开：若 React 刷新使某个按钮变成 stale，继续重新查找，而非让该按钮的异常中断本轮处理。
- 修改版不预先使用 JS `scrollIntoView`，而是交给 `ActionChains.move_to_element()` 尝试滚动到可见位置；点击后通过「数量加号按钮出现」或「完成選擇按钮消失」判断是否成功进入选数量页面。
- 基准版采用 JS 滚动、固定等待约 0.2 秒再点击、点击后等待约 1 秒，再检查页面状态。两种方式的等待/重试策略不同。

### 5. 其余部分

本次两份上传文件中，`_click_seat`、`set_quantity_and_order`、`fill_info_and_agree`、验证码相关函数等后续逻辑没有检测到实质性代码差异；它们的行号变化主要来自前面新增/扩展的函数。文件末尾另有空白行差异，可忽略。

## 二、runner.py

### 1. `make_driver`

- **基准版：约第 102–122 行；修改版：约第 102–117 行。**
- 基准版先使用项目固定 Chrome Profile；如果启动失败，会自动退回临时 Profile。临时 Profile 不保留原 Profile 的登录状态，因此程序虽然可能启动成功，却需要重新登录。
- 修改版不再自动退回临时 Profile。固定 Profile 启动失败时，会提示先关闭由脚本打开的 Chrome 窗口，然后直接抛出异常，避免程序无提示地切到一个没有登录状态的临时环境。

### 2. `run`：接手后切换到选座标签页

- **基准版：约第 133–196 行；修改版：约第 128–233 行；新增逻辑在修改版约第 154–194 行。**
- 基准版在用户点击「接手」后，直接执行验证码检测，依赖当时当前选中的标签页。
- 修改版在接手后轮询浏览器标签页，最多等待 15 秒，寻找 URL 包含 `tickets.interpark.com/onestop/seat` 的窗口，并切换过去再继续执行验证码/选座逻辑。
- 如果 15 秒内没找到目标窗口，会打印每个窗口的 URL、响铃并结束流程，避免在错误标签页上继续操作。

### 3. 其他部分

除 `make_driver` 的说明和异常处理、`run` 中新增标签页定位逻辑外，本次上传的两份 `runner` 在其他主流程上未检测到实质性改动。

## 三、给原作者的简要提交说明

> 我在原有代码基础上主要修改了新版 NOL SeatMap 的加载判断与选座流程：增加座位图加载状态观察；让程序在接手后主动定位 `tickets.interpark.com/onestop/seat` 标签页；按页面读取到的实际票档价格排序，并将座位按颜色分组后扫描，减少重复 DOM 查询；同时改进「完成選擇」按钮的 stale 元素异常处理和页面跳转确认。Chrome Profile 启动失败时不再静默退回临时配置，以免丢失登录状态。具体差异见附带的 unified diff 文件。
